# Final Report Bundle

## Purpose

This folder is the curated Markdown bundle for the final report, supervisor
review, and defense preparation. It contains copies of the report files that are
currently useful and defensible. The original files remain in `docs/`; this
bundle is a cleaner working set.

## Folder Structure

| Folder | Role |
|---|---|
| `01_architecture` | System architecture, data lake, backend operations, and runtime strategy |
| `02_source_pipelines` | INSEE, INPI, BODACC, and financial-data report sections |
| `03_ml_modeling` | ML pipeline, validation, experiment tracking, and leakage controls |
| `04_quality_audits` | Data-quality reports and recent audit evidence |
| `05_defense` | Defense report and weakness/improvement analysis |

## Recommended Reading Order

1. `01_architecture/system_data_architecture.md`
2. `01_architecture/data_lake_pipeline.md`
3. `02_source_pipelines/`
4. `03_ml_modeling/ml_continuity_risk_pipeline.md`
5. `03_ml_modeling/model_validation_report.md`
6. `03_ml_modeling/ml_experiment_tracking_report.md`
7. `04_quality_audits/`
8. `05_defense/project_defense_report.md`

## Omitted From This Bundle

This bundle intentionally excludes older guides, checklists, prompt notes,
reimport notes, internal AI context, and duplicated or stale report drafts. Keep
those files in `docs/` for traceability, but do not use them as the primary
final-report source unless they are reviewed again.
